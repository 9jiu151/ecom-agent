## 1. 项目概述

### 1.1 项目背景

电商运营由商品策划、视觉设计、内容创作、数据复盘等多个环节串联而成。中小商家在每个环节都依赖人工或外包：一套 Banner 外包价 500-1000 元/张，周期 2-3 天；商品调研、卖点提炼、文案撰写分散在不同工具中，无法形成闭环。

本项目以「AI 赋能电商全流程场景化应用」为总体框架，将 12 个电商环节组织为一个可视化的能力矩阵，并优先落地其中最刚需、最容易验证的一环——**美工设计（Banner 自动生成）**，再通过**全流程流水线**把各环节串成一次完整的"商品上架方案"产出，使平台具备"智能体"的编排特征，而非单一工具。

### 1.2 项目定位

- 面向中小电商商家与电商专业教学场景的 **AI 电商工作台**
- 以「一个商品进，一套上新方案出」为产品主线
- 首期聚焦箱包类目，可平滑扩展至其他类目

### 1.3 建设目标

| 编号 | 目标 | 衡量方式 |
|---|---|---|
| G1 | 覆盖电商全流程 12 环节的能力地图 | 首页完整呈现 12 环节及其 AI 资源状态 |
| G2 | 打通「策划 → 素材 → 视觉 → 内容 → 数据」的自动化流水线 | 输入 1 个商品，5 分钟内产出完整上新方案 |
| G3 | Banner 生成达到可交付水准 | 输出 950×250 与 1920×600 两种规格，符合实训手册评分要求 |
| G4 | 具备公网可访问能力 | 通过公网 URL 直接打开，无需安装任何软件 |
| G5 | 无 AI Key 环境下功能可完整演示 | 全部核心流程在离线规则模式下可跑通 |

- 支付、订单、库存等交易链路

## 2. 用户与使用场景

### 2.1 用户角色

| 角色 | 描述 | 核心诉求 |
|---|---|---|
| 电商运营（主用户） | 中小商家运营、店铺美工 | 快速产出符合平台规范的 Banner 与上新文案 |
| 电商专业学生 | 使用实训手册完成课程任务 | 按尺寸规范完成单肩包、手提包 Banner 并提交 |
| 指导教师 / 评审 | 查看项目成果 | 通过公网链接直接访问，无需部署，快速判断完整度 |
| 系统管理员 | 项目维护者 | 配置 AI Key、查看生成历史、维护模板 |

### 2.2 典型场景

**场景 A：实训任务交付**
学生选择「单肩包」素材，填写商品卖点（心动价 99 包邮、日韩风、PVC 材质），选择 950×250 模板一，生成 Banner 并下载提交。

**场景 B：新品上架**
运营输入商品名称与核心参数，启动全流程流水线，系统依次产出：调研报告 → 素材整理 → 3 版 Banner → 5 条文案 → 数据预估，运营挑选后下载。

**场景 C：风格批量测试**
运营对同一商品切换「春季新品 / 高端奢华 / 节日促销」三种主题，横向对比后确定主图风格。

## 3. 需求分析

### 3.1 总体业务流程

```
商品信息录入
   ↓
[1] 商品策划：卖点提炼 / 目标人群 / 定价建议
   ↓
[2] 素材准备：商品图筛选 / 主图确定
   ↓
[3] 美工设计：Banner 生成（选尺寸 → 选风格 → 选布局 → 预览调整 → 导出）
   ↓
[4] 内容创作：标题 / 卖点文案 / 短视频脚本
   ↓
[5] 数据分析：曝光-点击-转化预估与优化建议
   ↓
上新方案包（图片 + 文案 + 报告）
```

### 3.2 12 环节能力矩阵

| # | 环节 | AI 介入方式 | 本期状态 |
|---|---|---|---|
| 1 | 商品策划 | 竞品与销量数据汇总、卖点提炼、定价建议 | 已实现 |
| 2 | 商品拍摄 | 拍摄分镜、主图合规检查 | 已实现 |
| 3 | 美工设计 | 模板合成 + AI 背景生成 | **已实现（核心）** |
| 4 | 内容创作 | 标题/详情文案/短视频脚本 | 已实现 |
| 5 | 店铺运营 | 首页装修方案、活动排期 | 已实现 |
| 6 | 商品上架 | 标题关键词、类目属性、SKU 导出 | 已实现 |
| 7 | 营销推广 | 投放素材、人群包与预算分配 | 已实现 |
| 8 | 直播营销 | 直播话术、场控脚本 | 已实现 |
| 9 | 客户服务 | 商品知识库问答 | 已实现 |
| 10 | 跨文化沟通 | 多语言文案本地化 | 已实现 |
| 11 | 跨境运营 | 目标市场、平台规则与合规提示 | 已实现 |
| 12 | 数据分析 | 销量趋势、转化漏斗、优化建议 | 已实现 |

> 说明：环节 2、5-11 为本地生成型能力（规则引擎 + 可选大模型），产出方案与可下载交付物；不接第三方平台真实接口，页面已明确标注数据边界。

### 3.3 关键约束与冲突处理

《项目规划方案》要求"纯视觉设计，不添加促销文案"；《实训手册》的商品卖点则包含"心动价 99 包邮""原价 239 现价 199"等促销信息。二者存在冲突。

**处理方案：双模式**

| 模式 | 文案策略 | 适用 |
|---|---|---|
| 品牌视觉模式 | 仅品牌语 + 极简信息，无价格无促销 | 品牌形象、高端产品 |
| 促销转化模式 | 价格、卖点、包邮、活动标签 | 实训任务、大促 |

默认进入「促销转化模式」，可一键切换。

## 5. 页面与交互设计

### 5.1 信息架构

```
/                 首页：12 环节矩阵 + 案例入口
/pipeline         全流程智能体流水线
/banner           Banner 生成器（核心工作台）
/plan             商品策划
/content          内容创作
/data             数据分析
/studio           能力中心（8 环节工作台）
/history          历史记录
/settings         AI 配置
/about            项目说明（评审向）
```

### 5.2 Banner 生成器布局

三栏式工作台：

- **左栏（360px）**：素材上传 / 内置素材、尺寸、主题风格、布局、商品调节、文案、导出
- **中栏（自适应）**：实时画布预览，支持拖拽商品
- **右栏（320px，可折叠）**：生成记录与"提示词/参数"摘要

顶部：返回、当前尺寸标签、模式切换、AI 状态标识。

### 5.3 交互规范

- 所有生成类操作必须有加载态，超过 1 秒的操作显示进度文案
- 失败必须有可读的错误提示与重试入口，不允许静默失败
- 危险操作（删除历史）二次确认
- 移动端最小支持 1024px 宽度，窄屏折叠为单栏

## 6. 非功能需求

| 类别 | 要求 |
|---|---|
| 性能 | 首页首屏 ≤ 2s；Banner 参数变更到画面更新 ≤ 300ms；导出 ≤ 1s |

| 合规 | 页面标注"AI 生成内容需人工复核"；不抓取第三方平台受保护数据 |

## 7. AI 能力设计

### 7.1 分层策略

| 层级 | 能力 | 依赖 | 降级 |
|---|---|---|---|
| L1 规则引擎 | 文案模板、配色方案、布局计算、数据建议 | 无 | — |
| L2 文案大模型 | 卖点提炼、标题、脚本 | LLM API | 降级至 L1 模板 |
| L3 图像生成 | 主题背景图 | 图像 API | 降级至渐变/装饰背景 |

**原则**：L1 必须完整可用，L2/L3 为增强项。任何 AI 调用失败都不得阻断主流程。

### 7.2 提示词规范

- 系统提示固定角色：资深电商视觉/运营专家
- 输出强制 JSON，字段固定，便于前端渲染
- 商品信息以结构化参数传入，禁止拼接用户自由文本进系统提示
- 所有 AI 输出标注"AI 生成，需人工复核"

### 7.3 已接入模型（服务端预置）

| 用途 | 服务 | 配置 |
|---|---|---|
| 文案生成 | DeepSeek（OpenAI 兼容） | `https://api.deepseek.com` / `deepseek-chat` |
| 背景图生成 | 豆包 Seedream（火山方舟） | `/api/v3/images/generations` / `doubao-seedream-5-0-flash-260915` |

Key 仅存服务端，前端掩码展示；部署可用 `AI_LLM_*` / `AI_IMAGE_*` 环境变量覆盖。

## 9. 技术方案

### 9.1 技术选型

| 层 | 技术 | 说明 |
|---|---|---|
| 前端 | Vue 3 + Vite | 组件化单页应用，自研样式系统 |
| 画布 | Canvas 2D（自研渲染器） | 精确控制像素、导出稳定、无需额外依赖 |
| 后端 | Node.js 18+ + Express | 轻量、单进程、易部署 |
| 存储 | JSON 文件 | 无数据库依赖，便于迁移 |
| 部署 | 单端口静态托管 + Docker | 公网部署成本最低 |
| AI | OpenAI 兼容协议 | 可替换任意国内大模型 |

> 关于 Fabric.js：规划方案中列为选型，但本项目采用自研 Canvas 渲染器，原因是导出分辨率与参数化模板需要确定性渲染，自研层更可控且体积更小。此为对原方案的技术修正，已记录于《AI 开发记录》。

### 9.2 目录结构

```
ecom-agent/
├── server/            后端服务（API、静态托管、AI 代理）
├── web/               前端工程（Vue3 + Vite）
├── assets/            箱包素材（5 类商品图）
├── data/              生成历史与配置
├── docs/              需求文档、AI 开发记录、部署说明
```


### 9.3 部署要求

- 开发：`npm run dev` 前后端并行
- 生产：`npm run build` 后 `npm start`，单端口 3000 提供全站
- 公网：支持 Docker 部署到任意云主机 / Railway / Render
- 首次访问无需注册，直接可用
