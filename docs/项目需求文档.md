## 1. 项目概述

### 1.1 项目背景

电商运营由商品策划、拍摄、美工、内容、运营、上架、推广、直播、客服、跨文化、跨境、数据等环节串联而成。中小商家通常依赖人工或外包完成这些工作：一张 Banner 外包价 500–1000 元、周期 2–3 天；卖点提炼、文案、上架属性、投放计划分散在不同工具里，难以形成闭环。

本项目把 12 个环节组织为一张可视化的能力矩阵，用一个商品作为输入，串成「策划 → 素材 → 视觉 → 文案 → 数据」的智能体流水线，并为每个环节提供可操作、可导出结果的工作台，形成「一个商品进，一套上新方案出」的完整链路。

### 1.2 项目定位

- 面向中小电商商家与电商专业教学的 **AI 电商工作台**
- 以箱包类目为首期案例，能力设计可迁移到其他类目
- 既有单点工具（Banner 生成器），也有编排能力（全流程流水线），体现「智能体」而非工具集合
- 老师/评审打开公网链接即可直接使用，无需安装、无需配置 Key

## 2. 用户与使用场景

### 2.1 用户角色

| 角色 | 描述 | 核心诉求 |
|---|---|---|
| 电商运营（主用户） | 中小商家运营、店铺美工 | 快速产出符合平台规范的 Banner、文案与上架资料 |
| 电商专业学生 | 使用实训手册完成任务 3 | 按尺寸规范完成单肩包、手提包 Banner 并提交 |
| 指导教师 / 评审 | 查看项目成果 | 通过公网链接直接打开，快速判断完整度与可用性 |
| 系统管理员 | 项目维护者 | 预置 AI 模型、查看历史、控制访问成本 |

### 2.2 典型场景

**场景 A：实训任务交付**
学生选择「单肩包」素材，填写心动价 99 包邮、日韩风、PVC 材质等卖点，选择 950×250 模板一，生成并下载 Banner 提交。

**场景 B：新品上架**
运营选择商品后启动流水线，系统依次产出调研卡、素材清单、3 版 Banner、5 条文案与数据简报，运营挑选后下载方案。

**场景 C：全环节方案准备**
运营在能力中心切换「拍摄 / 上架 / 推广 / 直播 / 客服 / 跨文化 / 跨境」，同一商品信息复用，逐环节导出分镜表、上架 CSV、投放计划、直播台本、FAQ、多语文案与跨境清单。

**场景 D：风格对比**
对同一商品切换春季、夏日、奢华、节日等主题，横向比较后确定主图风格，并可用 AI 生成氛围背景。

## 3. 需求分析

### 3.1 总体业务流程

```
商品信息录入（内置商品 / 手动填写）
   ↓
[1] 商品策划：卖点提炼 / 目标人群 / 定价建议
   ↓
[2] 素材准备：商品图筛选 / 主图确定 / 抠图
   ↓
[3] 美工设计：尺寸 → 主题 → 布局 → 文案 → 预览调整 → 导出
   ↓
[4] 内容创作：标题 / 短文案 / 短视频脚本
   ↓
[5] 数据分析：曝光-点击-转化预估与优化建议
   ↓
上新方案包（Banner 图片 + 文案 + 数据报告）
```

### 3.3 关键约束与冲突处理

《项目规划方案》要求「纯视觉设计，不添加促销文案」；《实训手册》的商品卖点包含「心动价 99 包邮」「原价 239 现价 199」等促销信息。二者存在冲突。

**处理方案：双模式**

| 模式 | 文案策略 | 适用 |
|---|---|---|
| 品牌视觉模式 | 仅品牌语 + 极简信息，无价格无促销 | 品牌形象、高端产品 |
| 促销转化模式 | 价格、卖点、包邮、活动标签 | 实训任务、大促 |

默认「促销转化模式」，可一键切换。

### 3.4 关键体验指标

| 指标 | 目标值 | 实测 |
|---|---|---|
| Banner 参数变更到画面更新 | ≤ 300ms | 120ms 防抖，实测流畅 |
| 950×250 / 1920×600 导出 | 尺寸与设定完全一致 | 通过像素级校验 |
| 流水线完整跑完 | 无中断，5/5 阶段 | 通过 |
| AI 文案响应 | ≤ 30s | 实测约 5–10s |
| AI 背景生成 | ≤ 60s | 实测约 12s（3552×1184） |
| 移动端 | 390px 无横向溢出 | 首页 / Banner / 流水线 / 策划均为 0px |

## 7. AI 能力设计

### 7.1 分层策略

| 层级 | 能力 | 依赖 | 降级 |
|---|---|---|---|
| L1 规则引擎 | 文案模板、配色、布局、分镜、上架属性、数据建议 | 无 | — |
| L2 文案大模型 | 卖点提炼、标题、短文案、脚本 | DeepSeek API | 降级至 L1 模板 |
| L3 图像生成 | 主题氛围背景图 | 豆包 Seedream API | 降级至渐变/装饰背景 |

**原则**：L1 必须完整可用，L2/L3 为增强；任何 AI 调用失败都不得阻断主流程。

### 7.2 已接入模型（服务端预置）

| 用途 | 服务 | 地址 | 模型 |
|---|---|---|---|
| 文案生成 | DeepSeek（OpenAI 兼容） | `https://api.deepseek.com` | `deepseek-chat` |
| 图像生成 | 豆包 Seedream（火山方舟） | `https://ark.cn-beijing.volces.com/api/v3/images/generations` | `doubao-seedream-5-0-flash-260915` |

- 配置存于 `data/settings.json`；老师打开网站无需设置
- Key 仅服务端持有，前端只拿到掩码
- 部署可用环境变量覆盖：`AI_LLM_BASE_URL` / `AI_LLM_KEY` / `AI_LLM_MODEL` / `AI_IMAGE_BASE_URL` / `AI_IMAGE_KEY` / `AI_IMAGE_MODEL`

### 7.3 调用链与降级

```
前端操作
  → /api/ai/text 或 /api/ai/image
  → 服务端读取配置
  → 调用外部模型（超时 150s）
  → 成功：返回结构化结果 / 同源图片 URL
  → 失败：返回 ok:false + 可读原因；前端提示并回退规则结果
```

- 图像接口返回的远程图片由服务端下载到 `data/generated/`，通过 `/generated/...` 同源提供，避免画布被跨域污染导致无法导出
- 图像生成成功实测：3552×1184 JPG，约 12 秒
- 若火山方舟返回 `429 SetLimitExceeded`，按官方提示在「开通管理」调整模型用量上限或关闭「安心体验模式」

### 7.4 提示词规范

- 系统角色固定：资深电商视觉 / 运营专家
- 输出强制 JSON，字段固定，便于渲染
- 商品信息以结构化参数传入，避免把用户自由文本拼进系统提示
- 所有 AI 输出标注「AI 生成，需人工复核」

### 7.5 成本与防滥用

- 公网演示按 IP 限流（见 FR-08-4），本地访问不限流
- 单次图像生成成本高于文案，图像限额更严
- 演示结束后可关闭隧道，避免持续消耗额度
